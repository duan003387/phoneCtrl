## 修复鼠标拖拽松手无惯性（main 分支，commit dfc0300）

**根因**（华为 ELS-AN00 / EMUI 12 实测，chatDemo 反转列表 + 遥测量化）：
1. sendevent 注入桥被 SELinux 拒绝（shell 写 /dev/input EACCES）→ bridge_ok=false
2. 全部触摸走 adb 聚合通道：move 事件被丢弃（拖拽不实时跟随），up 时固定 200ms 重放 `input swipe`
3. **EMUI 的 `input swipe` 注入事件不产生设备端惯性**（实测 0 帧），而 `input motionevent` 流式注入可以（实测正常 fling）
4. 上一个会话的"指数衰减尾巴"方案方向反了：把事件流末段速度衰减到近 0 才抬起，反而掐灭设备端 VelocityTracker 的原生 fling

**修复**：
- 新增 `src-tauri/src/motion.rs`：每设备常驻 `adb shell` 会话，逐条写 `input motionevent DOWN|MOVE|UP`；实时 move 做最新位置合并（防积压），脚本手势走 Seq 原样插值写入（duration/18 步）
- 通道优先级：注入桥 > scrcpy(显式) > motionevent > adb 聚合；input_touch/tap/swipe 全接入
- MirrorCanvas：惯性交给设备端；仅补偿鼠标"停下再松开"（短停顿≤250ms 按停前速度补 5 步冲刺再抬起）；MOVE 节流 30→14ms
- 量化验证：甩动中松手 104px 惯性 / 停150ms补冲刺 538px / 宏重放 191px / 停400ms直接抬起 0px（正确）

**其他**：
